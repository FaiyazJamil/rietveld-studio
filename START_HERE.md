# Start Rietveld Studio

**Author and maintainer:** Md Faiyaz Jamil. **License:** MIT.  
Publishing this project on GitHub/Zenodo? Read [PUBLISH_ON_GITHUB_ZENODO.md](PUBLISH_ON_GITHUB_ZENODO.md).
Citation files are supplied in the repository root; a DOI is added only after Zenodo assigns it.

**Upgrading an existing installation:** read [UPGRADE_TO_0_2.md](UPGRADE_TO_0_2.md). The launcher recognizes `.venv-rietveld` as well as `.venv`.

This is a Python desktop application with a Qt GUI and the real GSAS-II numerical engine. It searches the Crystallography Open Database, asks you to confirm a structural model, accepts local CIFs and powder XRD data, refines in stages, and produces plots, structural tables, diagnostics, and an Origin export package.

## Windows 10/11 — recommended for Origin export

1. Install **64-bit Python 3.11** from [python.org](https://www.python.org/downloads/). Include the **Python Launcher** in the installation.
2. Extract the complete `Rietveld_Studio.zip` into a writable folder. Keep the files together.
3. Open PowerShell in the extracted `rietveld-studio` folder and run:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\setup_windows.ps1
   ```

   The script creates a private Python environment, installs the app, downloads the pinned official GSAS-II source and matching compiled modules, checks the engine, and generates a synthetic example. Internet access is needed for setup. Administrator access is not required.

4. Double-click **`launch_windows.bat`**.
5. In **Engine & run log**, click **Check engine installation**.

The Windows scripts are provided for local use; this delivery was numerically tested on Linux. Origin COM automation must be checked on your Windows/Origin installation.

## Your first refinement

1. **Crystal structures:** enter `LiFePO4`, `LiMn0.6Fe0.4PO4`, another formula, a compound name, or a COD ID. Review the returned formulas, space groups, lattice parameters, and publications. Select a result, click **Review selected CIF**, and explicitly confirm the appropriate CIF block. Repeat for additional phases. **Import local CIF** is always available.
2. **Powder data:** load numeric XY/XYE/CSV/TSV/TXT/DAT or a single-scan XRDML. Declare the columns and uncertainty model, then click **Load & validate pattern**. Use sigma = standard deviation, not variance or weight.
3. **Instrument:** enter the actual wavelength and geometry. Load a calibrated GSAS-II `.instprm` if available. A loaded instrument file overrides the numeric radiation/profile guesses.
4. **Refinement recipe:** choose a project name and output root. Use the default three independent starts, up to six calls per stage, and explicit Rwp/parameter-shift convergence limits. For an already-subtracted scan choose **Background already subtracted**. Release atomic parameters only if your data support them. To determine size/strain, provide a calibrated instrument profile and choose **Sample size/strain; instrument fixed**.
5. Click **Run automatic refinement**. Inspect the profile, convergence plot, iteration table, fit statistics, accepted/rejected stages, correlations, peak associations, and diagnostics. A stopped run is not automatically labeled converged; constant-weight χ²/GOF are labeled descriptive.
6. Open the report or export a native **`.opju`** project.

## Try the included synthetic example

Open **File → Open project** and select `examples/synthetic_nacl/demo.rsv.json`. This example is generated by setup and is also included in the distribution. Its counts are simulated; it is not experimental data.

The generator uses a true lattice parameter of **5.640200 Å** and a starting CIF of **5.650000 Å**. A validated run recovered approximately **5.640151 Å**, with reduced χ² ≈ **1.035**. Exact values may vary slightly by numerical dependency versions.

## Origin/OriginPro

For native editable `.opju` output, install and license **Origin 2021 or later** on Windows. The Windows setup installs `originpro`. Enable automatic export or use **Export Origin .opju** after fitting. The exporter creates a dedicated Origin automation instance and preserves existing projects.

The result folder also contains a standalone `export_to_origin.py`. On the Windows/Origin machine:

```powershell
python -m pip install numpy pandas originpro
python export_to_origin.py "C:\path\to\your\result_folder"
```

Without Origin, the app still saves the full refinement: SVG/PDF/300 dpi PNG plots, XLSX/CSV tables, HTML report, refined CIFs, covariance, and the GSAS-II project. It does not manufacture an invalid OPJU file.

## Linux/macOS

Use Python 3.11 and run:

```bash
bash setup_unix.sh
bash launch_unix.sh
```

An existing GSAS-II installation can be selected instead: set its Python executable and optional source folder in **Engine & run log**. Native Origin export remains a Windows operation.
